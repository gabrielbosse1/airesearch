# One-byte edit diagnostic

- Input: `Hello Worl` — `[72, 101, 108, 108, 111, 32, 87, 111, 114, 108]`
- Requested edit: zero-based byte 9, 108 (`l`) → 100 (`d`).
- Target: `Hello Word` — `[72, 101, 108, 108, 111, 32, 87, 111, 114, 100]`.

| Test | Result | Observed behavior |
|---|---|---|
| Mask-conditioned diffusion | **Unsupported** | The checked-out model has no native edit-mask interface, and its router rejects instruction-directed replacement. A separate host-side mask fallback generated byte **0**, not 100; the mask was not a model input. |
| Autonomous cognitive loop | **Fail** | The selected checkpoint produced `Hell? Worl` ([72, 101, 108, 108, 63, 32, 87, 111, 114, 108]) and stopped after 5 actions. The final-epoch checkpoint produced the same output. It changed byte 4 to `?` instead of byte 9 to `d`. No controller or memory was supplied. |
| Memory retrieval | **Pass, only after explicit storage** | The existing guarded memory had no matching entry. After writing this exact input/target mapping into an isolated copy, saving it, and reloading it, exact retrieval returned `Hello Word`. This is lookup of a supplied answer, not autonomous editing. |

The mask fallback used one fixed seed and averaged the raw instruction bytes into a concept vector; this model was not trained to follow those instructions. The original memory checkpoint was not modified.

Reproduce from the repository root:

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -m evaluation.diagnostic_single_byte_edit
```

The detailed action trace and exact byte outputs are in `runs/single_byte_edit_diagnostic.json`.
